# 050 — Публичный приём заявок с сайта

## Назначение

Сайт `www.magicmet.ru` является первым публичным этапом SaaS-воронки. Адаптер принимает заявку без JWT, создаёт или находит контакт и сохраняет новую заявку в модуле `requests`.

## Endpoints

- `POST /api/public/v1/leads` — принять заявку сайта;
- `POST /api/public/v1/events` — принять событие анонимной воронки.

Оба endpoint помечены `@Public()`, ограничены rate limit и дополнительно проверяют `Origin`.

## Идемпотентность

Сайт передаёт одинаковое значение в:

- поле `externalLeadId`;
- заголовок `X-Idempotency-Key`.

Повторный запрос возвращает уже созданный `leadId` и `duplicate: true`. До отдельной таблицы интеграций стабильный внешний ID хранится в служебной отметке заявки:

```text
[website-lead:<externalLeadId>]
```

## Что попадает в SaaS

1. Контакт создаётся по имени и значению поля «телефон или e-mail» либо используется существующий контакт с тем же значением.
2. Создаётся `Request` со статусом `DRAFT` и источником `PASTED`.
3. Текст потребности сохраняется как строка заявки.
4. Полный JSON сайта — UTM, referrer, sessionId, выбранные товарные группы и недавние события — сохраняется в `sourceText` для проверки менеджером и последующего структурирования.
5. Краткий контекст источника сохраняется в `notes`.

События до отправки заявки пишутся в структурированный лог. При отправке формы последние события дополнительно приходят внутри `journey`, поэтому история посетителя сохраняется вместе с заявкой даже при временной недоступности отдельного event endpoint.

## Переменные окружения

```env
CORS_ORIGINS=http://localhost:3001,http://localhost:4173,https://www.magicmet.ru,https://magicmet.ru
PUBLIC_INTAKE_ORGANIZATION_ID=<UUID организации Мэджик Металл>
PUBLIC_INTAKE_ORGANIZATION_INN=7453362080
PUBLIC_INTAKE_ALLOWED_ORIGINS=https://www.magicmet.ru,https://magicmet.ru,http://localhost:4173
```

В production рекомендуется задать `PUBLIC_INTAKE_ORGANIZATION_ID`. Поиск по ИНН оставлен как резервный вариант для локального запуска.

## Следующее усиление

После проверки первой рабочей связки выделить таблицы `external_leads` и `funnel_events` с уникальным ключом `(organization_id, source_system, external_lead_id)`. Это даст транзакционную идемпотентность и отдельную аналитику событий без зависимости от логов.
